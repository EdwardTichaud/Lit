# Lit - Gameplay

Ce document fixe une direction gameplay sur la base du lore actuel. L'objectif est de garder un jeu agreable a jouer en solo, tout en restant amusant et lisible en coop jusqu'a 4 joueurs.

## Direction generale

`Lit` doit etre un jeu d'exploration, d'enquete et de manipulation des strates temporelles.

Le coeur de l'experience ne doit pas etre un simple combat ou un simple puzzle game. Le plaisir vient de la combinaison de quatre piliers :

- explorer pour comprendre ;
- manipuler le temps global du chateau ;
- separer puis recomposer le groupe ;
- saboter progressivement les conditions du rituel.

## Boucle principale

La boucle visee est la suivante :

1. Entrer dans une zone du chateau.
2. Observer la zone dans plusieurs strates temporelles.
3. Utiliser braseros, orbes et cooperation de groupe pour la comprendre.
4. Resoudre ses obstacles spatiaux, temporels et narratifs.
5. Recuperer une ressource, une relique, un fragment de verite ou une action decisive.
6. Sortir, consolider la comprehension du rituel, preparer l'expedition suivante.

Cette boucle doit fonctionner :

- en solo via switch rapide et planification ;
- en coop via coordination, communication et execution simultanee.

## Principes de design

### 1. Le lore doit produire du gameplay

Les revelations narratives ne doivent pas rester dans des textes passifs. Elles doivent se traduire par :

- des lieux qui changent selon l'epoque ;
- des objets et structures qui n'existent que dans certaines strates ;
- des puzzles bases sur la causalite historique ;
- des actions qui modifient les conditions du rituel.

### 2. Le solo ne doit pas etre un sous-mode de la coop

En solo, le joueur doit avoir l'impression de diriger une expedition intelligente, pas de subir des mecanismes penses uniquement pour plusieurs joueurs.

Le solo doit donc privilegier :

- switch rapide entre personnages ;
- ordres simples et fiables ;
- etats de puzzle memorises ;
- lisibilite forte des roles et positions.

### 3. La coop doit produire des situations naturelles

En multijoueur, le plaisir doit venir de :

- la simultaneite ;
- l'information incomplete ;
- la repartition des roles ;
- la communication entre joueurs ;
- les erreurs ou improvisations qui creent des moments memorables.

## Piliers de gameplay

## A. Braseros - Temps global

Les braseros changent l'epoque globale du chateau.

Ils doivent modifier concretement :

- la structure des pieces ;
- l'etat de murs, ponts, escaliers, grilles ;
- l'accessibilite de certaines zones ;
- la presence d'objets ou de traces narratives ;
- certains chemins ou dangers.

Le brasero ne doit pas etre juste une clef de porte. C'est un outil de lecture du mensonge historique.

## B. Orbes - Perception locale

Les orbes modifient temporairement la perception sans changer l'epoque.

- Bleu : structure, ordre, passages caches, connexions invisibles.
- Rouge : ressources, tresors, risques, zones optionnelles.
- Violet : echos du passe, traces du rituel, memoires, dialogues fragmentes.

Interet solo :

- le joueur switch entre personnages ou alterne les lectures pour croiser les indices.

Interet coop :

- chaque joueur peut voir, comprendre ou annoncer quelque chose que les autres ne percoivent pas immediatement.

## C. Groupe et separation

Le groupe doit servir le gameplay, pas seulement le combat.

Les situations clefs :

- un personnage maintient une interaction ;
- un autre traverse ;
- un troisieme observe les effets dans une autre salle ;
- un quatrieme reste en couverture ou prepare le retour.

En solo, cela repose sur le switch et sur des ordres simples.
En coop, cela repose sur la coordination directe entre amis.

## D. Sabotage du rituel

Le but profond du jeu ne doit pas etre seulement de sortir vivant d'une zone.

Le joueur doit pouvoir accomplir des actions decisives qui sabotent le rituel :

- detruire un symbole liturgique ;
- sauver ou disperser des Chanteurs ;
- casser une preparation vieille de plusieurs siecles ;
- perturber la mise en scene du siege ;
- devoiler la verite a travers certaines strates.

Chaque action importante doit reduire la "completude" du rituel final.

## Typologie de puzzles

## 1. Puzzles multi-strates

Le meme lieu existe dans plusieurs epoques, avec des etats differents.

Exemples :

- un pont entier dans une strate, ruine dans une autre ;
- une cellule fermee a l'an 0, transformee en couloir rituel a l'an 666 ;
- un mecanisme present dans le passe mais absent dans le present.

Le joueur agit dans une strate pour produire un effet utile dans une autre.

## 2. Puzzles de simultaneite

Ils doivent etre faisables :

- en solo par planification, placement et switch ;
- en coop par action simultanee reelle.

Exemples :

- deux leviers eloignes ;
- une porte qui reste ouverte seulement tant qu'un personnage maintient un mecanisme ;
- un brasero active a distance pendant qu'un autre joueur traverse une zone changeante.

## 3. Puzzles d'information incomplete

Le joueur n'a pas toute l'information avec un seul point de vue.

Exemples :

- l'orbe bleu montre le passage, le violet montre pourquoi il existe ;
- un joueur voit une structure, un autre voit le danger qu'elle cache ;
- plusieurs fragments d'un chant doivent etre reconstitues depuis des points separes.

## 4. Puzzles de causalite historique

Le but est de comprendre qu'un element du present est la consequence d'un acte passe.

Exemples :

- liberer ou non certaines cellules change la distribution future de certains descendants ;
- deplacer un objet rituel dans une strate ancienne perturbe sa place pendant le rite ;
- detruire un acces militaire modifie la forme du siege.

## Exemples de zones

## Aile des cellules

Objectif narratif :

- comprendre que les habitants descendent de prisonniers.

Objectif gameplay :

- explorer l'origine carcerale du chateau dans les premieres annees ;
- voir sa transformation en espace liturgique a l'an 666 ;
- agir sur la structure des cellules pour modifier plus tard la circulation ou l'acces a certains fragments.

## Salle du faux salut

Objectif narratif :

- comprendre que les habitants croyaient participer a leur salut.

Objectif gameplay :

- observer la disposition des fideles ;
- reveler que l'architecture et les placements forment un dispositif rituel ;
- saboter certains elements sans tout declencher trop tot.

## Pont des Ombres

Objectif narratif :

- lier les Ombres a l'effondrement du temps.

Objectif gameplay :

- traverser une zone instable dont la structure varie selon l'epoque ;
- utiliser orbes et coordination pour lire les appuis reels ;
- gerer le risque de separation du groupe.

## Chambre du chant

Objectif narratif :

- relier les Chanteurs au coeur du rituel.

Objectif gameplay :

- reconstituer plusieurs fragments de chants ;
- associer ces fragments a des familles, lieux ou moments ;
- comprendre ce qui devait etre chante et pourquoi.

## Ce qui doit etre agreable en solo

Pour que le solo soit vraiment bon, il faut :

- un switch rapide et lisible entre personnages ;
- des ordres simples : suivre, attendre, maintenir, interagir ;
- des puzzles avec progression memorisee ;
- une forte lisibilite de ce que chaque personnage a decouvert ;
- peu de micro-gestion inutile.

Le solo doit donner l'impression de commander une petite expedition competente.

## Ce qui doit etre amusant entre amis

Pour que la coop soit vraiment amusante, il faut favoriser :

- la communication utile ;
- les plans improvises ;
- les lectures asymetriques du monde ;
- la simultaneite ;
- les moments ou un joueur comprend quelque chose que les autres n'ont pas encore vu.

Il faut eviter une coop purement cosmetique.

## Progression long terme

Le jeu gagne a etre structure en trois niveaux d'objectifs :

- court terme : survivre a une zone et en sortir ;
- moyen terme : comprendre un pan du chateau et recuperer une piece de verite ;
- long terme : empecher le rituel de se completer.

Ainsi, chaque session produit un gain concret meme si le joueur n'atteint pas une grande revelation scenaristique.

## Structure en deux temps

Le lore se prete bien a une structure de progression en deux couches.

### Premier parcours

- le joueur decouvre la verite ;
- il stoppe le rituel trop tard ;
- il sauve le monde, mais pas le chateau.

### Second parcours possible

- le joueur agit avec la connaissance du premier parcours ;
- il anticipe mieux les causes ;
- il accomplit des actions decisives plus tot ;
- il peut chercher a empecher completement le rituel.

Cette structure offre une base solide pour allonger la duree de vie sans simplement multiplier le contenu.

## Ce qu'il faut eviter

- une coop qui se resume a appuyer sur plusieurs boutons ;
- des classes trop rigides trop tot ;
- du lore uniquement raconte par texte ;
- des changements temporels sans vraie consequence spatiale ;
- des puzzles frustrants en solo parce qu'ils sont penses d'abord pour plusieurs joueurs ;
- un jeu qui oublie que son coeur est l'enquete sur un mensonge historique.

## Ligne directrice

La formule a proteger est la suivante :

`Lit` doit etre un jeu d'enquete temporelle cooperatif, ou comprendre l'histoire permet de changer le monde, et ou manipuler les strates du chateau sert autant a resoudre des situations qu'a saboter progressivement le rituel.
