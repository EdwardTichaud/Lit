## Prompt Codex

```text
Objectif :
Comprendre puis corriger le bug suivant : dans le couloir du district 1, le personnage semble considérer tout le couloir comme un obstacle, ce qui déclenche en boucle l’animation de franchissement d’obstacle. Il faut identifier la cause réelle et appliquer un correctif minimal, sans élargir inutilement le périmètre.

Contexte :
Le système de locomotion passe par UCC via `LitOpsiveLocomotionBridge`. La documentation indique explicitement que le franchissement automatique d’obstacles reste dans `LitOpsiveLocomotionBridge`, avec des garde-fous pour ignorer :
- les obstacles sous un seuil ;
- les surfaces progressives dont la normale pointe trop vers le haut (`obstacleTraversalMaxSurfaceUpDot`) afin qu’une pente, colline ou amas de terre ne déclenche pas l’animation.
Le symptôme décrit ressemble à une détection qui prend le sol / la géométrie du couloir / une pente douce / un collider parasite comme obstacle franchissable à chaque frame.

Documentation à lire :
1. `AIStudio/docs/AGENTS.md` (obligatoire avant toute modification)
2. `AIStudio/docs/architecture.md`
3. `AIStudio/docs/systems/input_camera_ucc.md`
4. `AIStudio/docs/systems/squad_characters.md`
5. `AIStudio/docs/systems/runtime_session.md`

Fichiers Unity probables à inspecter en priorité :
- `Assets/Characters/6_UCC_Opsive/OpsiveIntegration/LitOpsiveLocomotionBridge.ObstacleTraversal.cs`
- éventuellement le fichier principal/partial frère de `LitOpsiveLocomotionBridge` si nécessaire pour le contexte immédiat
- `Assets/Scripts/LadderController.cs` seulement si tu constates un partage de logique de traversal utile au diagnostic
Ne pars pas en exploration large du projet sans nécessité démontrée.

Mots-clés de recherche conseillés :
- `ObstacleTraversal`
- `obstacleTraversalMaxSurfaceUpDot`
- `traversal`
- `SphereCast`
- `CapsuleCast`
- `Raycast`
- `normal`
- `ground`
- `slope`
- `LayerMask`
- `OnAnimator`
- `Obstacle_Traversal`
- `district 1`
- `corridor`
- `couloir`

Stratégie proposée :
1. Lire `AGENTS.md`, puis uniquement la doc listée ci-dessus.
2. Inspecter `LitOpsiveLocomotionBridge.ObstacleTraversal.cs` pour reconstruire précisément :
   - comment la détection d’obstacle fonctionne ;
   - quels colliders/surfaces sont pris en compte ;
   - à quel moment le trigger Animator est relancé ;
   - quelles protections existent déjà contre les pentes/sols/contacts persistants.
3. Identifier la cause probable du déclenchement en boucle :
   - surface de sol ou paroi mal classée comme obstacle ;
   - normale mal interprétée ;
   - absence d’hystérésis / cooldown / mémorisation d’obstacle déjà traversé ;
   - détection depuis une position qui reste dans le collider après déclenchement ;
   - overlap/cast qui voit le couloir entier ;
   - obstacle détecté même pendant un traversal en cours ou juste après.
4. Appliquer le plus petit correctif robuste possible. Priorité :
   - corriger la qualification des surfaces dans la détection ;
   - ou empêcher le retrigger tant que le personnage est encore dans le même contexte de contact ;
   - ou ignorer les surfaces assimilables au sol / aux pentes ;
   - sans refactor global.
5. Ajouter/ajuster des commentaires seulement si cela clarifie une logique durable.
6. Mettre à jour la documentation uniquement si tu découvres une règle durable non documentée ou si la doc actuelle devient inexacte.

Contraintes impératives :
- Préserver les changements Git existants.
- Patch minimal.
- Ne pas refactorer un système voisin sans nécessité démontrée.
- Ne pas modifier scènes, prefabs ou ScriptableObjects sans nécessité démontrée.
- Pour les inputs, modifier `Assets/PlayerInputs.inputactions`, jamais le wrapper C# généré.
- Ne jamais contourner `LocalPlayerContext`.
- Ne jamais créer un second chemin d'input.
- En multijoueur, respecter l'autorité serveur et tester host/client.
- Vérifier les risques Unity classiques : static, singleton, event non désabonné, coroutine double, ordre `Awake` / `OnEnable` / `Start`, Domain Reload désactivé.
- Si une doc devient inexacte ou si tu crées une connaissance durable, mettre à jour la documentation ciblée, sinon ne pas toucher à la doc.

Attendu de diagnostic :
Avant de patcher, formule en quelques points :
- la cause probable exacte ;
- pourquoi elle produit spécifiquement un déclenchement “partout dans le couloir” ;
- pourquoi le correctif choisi est le plus petit correctif sûr.

Tests à effectuer / décrire :
Au minimum, décrire des tests manuels précis :
1. Dans le couloir du district 1 :
   - avancer normalement ;
   - vérifier que l’animation de franchissement ne se déclenche plus en boucle ;
   - vérifier qu’aucun blocage de locomotion n’apparaît.
2. Sur un vrai petit obstacle franchissable :
   - vérifier que l’animation se déclenche toujours.
3. Sur une pente / rampe / surface douce :
   - vérifier qu’aucun faux positif de franchissement n’apparaît.
4. Sur un obstacle trop haut :
   - vérifier qu’il reste bloquant sans déclenchement incorrect.
5. Si le flux est réseau-dépendant :
   - vérifier host et client.

Risques à surveiller :
- casser le franchissement légitime d’obstacles bas ;
- masquer le symptôme par un cooldown global qui empêcherait des traversals valides ;
- dépendre d’une config de scène alors que le bug vient du code de détection ;
- introduire une divergence solo / réseau.

Livrable :
- patch minimal ;
- résumé de la cause ;
- liste des fichiers modifiés ;
- tests réalisés ou à réaliser ;
- mention explicite si aucun changement de doc n’est nécessaire.
```
